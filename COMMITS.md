# Сценарий демонстрации (три коммита)

Цель — показать, как CI **бракует** небезопасный код и **пропускает** исправленный.
Все изменения вносятся только в `backend/src`; инфраструктура (сканер, workflow) уже на месте.

После каждого коммита смотрите вкладку **Actions** репозитория: красный ✗ = брак, зелёный ✓ = пропуск.
Найденные уязвимости также появятся в **Security → Code scanning** (отчёт SARIF).

---

## Коммит 1 — небезопасная версия (ожидается ✗ брак)

Стартовое состояние репозитория. Что находит сканер:

| Файл | Уязвимость | Уровень | CWE |
|------|------------|---------|-----|
| `PasswordHasher.java` | хеширование паролей через **MD5** | CRITICAL | CWE-327 |
| `JwtUtil.java` | **хардкод-секрет** подписи токена | CRITICAL | CWE-798 |
| `SessionId.java` | **`new Random()`** для токенов | HIGH | CWE-338 |
| `JwtUtil.java` | **HTTP** вместо HTTPS (`AVATAR_CDN`) | MEDIUM | CWE-319 |

Итог: `--fail-on high` → 2 critical + 1 high → **exit 1, CI красный**.

## Коммит 2 — частичное исправление (ожидается ✗ брак)

- `PasswordHasher.java`: MD5 → **PBKDF2-HMAC-SHA256** со случайной солью (`SecureRandom`).
- `JwtUtil.java`: секрет вынесен в **переменную окружения** `JWT_SECRET`; `AVATAR_CDN` → HTTPS.
- `SessionId.java`: **намеренно оставлен `new Random()`**.

Итог: остаётся 1 находка HIGH (`new Random()`) → **CI всё ещё красный**.
Урок: одна high-уязвимость уже блокирует слияние — частичных правок недостаточно.

## Коммит 3 — полное исправление (ожидается ✓ пропуск)

- `SessionId.java`: `new Random()` → **`new SecureRandom()`**.

Итог: находок ≥ HIGH нет → **exit 0, CI зелёный**.

---

Точные изменения для коммитов 2 и 3 готовятся по ходу демонстрации — см. инструкции в чате.
